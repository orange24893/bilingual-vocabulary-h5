# IELTS / TOPIK 完整备考词库设计

## 1. 目标

将当前 8 个演示词扩展为可持续使用的 IELTS 英语与 TOPIK 韩语备考词库，服务于电脑浏览器本地学习版本。

本设计遵循以下已确认决策：

- 采用推荐备考词库，不声称存在唯一的 IELTS 或 TOPIK 官方全量词表。
- 所有词条保留单词、短语、例句三段真实发音。
- 配图改为按需补充；抽象词可以使用文字卡片，不强行生成图片。
- 学习记录继续保存在本机，不引入账号、微信审核或运行时云服务。
- 词库扩大后保持两种语言的队列、每日目标、复习记录和连续学习天数完全独立。

## 2. 词库范围与来源

### 2.1 IELTS 英语

词头由以下来源合并并按现有 `normalizeWord` 规则去重：

1. ECDICT 中带有 IELTS 考试标签的词条，提供词头、音标、英文释义、中文释义及考试标签。
2. Academic Word List 的 570 个学术词族，以词族代表词补充学术高频词汇，不无控制地展开所有派生形式。

保留来源、原始标签和词族信息。最终数量以规范化去重后的构建报告为准，不人为凑整数。

### 2.2 TOPIK 韩语

以韩国国立国语院《国际通用韩国语标准教育课程》的 1–6 级词汇体系为分级参考：

- 导入 1–6 级词目，为备考 TOPIK 6 提供完整基础。
- 将 5–6 级词目标记为高级重点，但不删除 1–4 级基础词。
- 释义与例句优先使用韩国国立国语院韩国语基础词典、韩汉学习词典及其允许使用的开放接口。
- 页面中明确显示“分级参考词库”，不描述为“TOPIK 官方唯一词表”。

韩语词条使用 Unicode NFC 规范化并在韩语内部查重。同形异义词只有在来源和释义能够区分时才分别保留，不能因重复生成而制造无意义副本。

### 2.3 内容补齐与授权

- 短语和例句优先来自许可明确的词典或双语语料。
- 来源缺失的内容可以使用真实生成服务在构建期补齐，但必须经过字段、语言和重复校验；不能使用固定模板、随机拼句或占位文本冒充词条内容。
- 未配置所需数据源或生成服务时，构建报告明确列出阻塞原因，相关词条不得标记为 `ready`。
- 保存来源名称、原始标识和许可说明。运行时学习不依赖这些外部接口。

## 3. 数据构建架构

新增独立的离线词库构建流程，职责依次为：

1. 读取原始词表与词典数据。
2. 规范化、语言内查重和来源合并。
3. 生成统一的词条内容。
4. 为单词、短语和例句生成真实 MP3。
5. 校验文本、音频和媒体清单。
6. 输出浏览器可直接读取的分语言词库与静态媒体目录。
7. 输出数量、缺失项、重复项、来源和体积报告。

原始下载数据、构建缓存和临时文件不进入前端源码包。最终运行时只读取构建后的词库文件与媒体文件。

### 3.1 稳定标识

- 现有 8 个词条保持原 ID 不变。
- 新内置词条 ID 由语言、规范化词头和来源稳定生成；需要区分的同形异义词再加入来源义项 ID，不能依赖数组下标或构建时间。
- 同一来源重复构建时 ID 不变，避免学习记录失效。
- 多来源合并时保留全部来源标记，不重复创建学习词。

### 3.2 内容状态

`ready` 仅表示：

- 当前语言要求的全部文字字段完整。
- 单词、短语、例句均有对应的真实 MP3 文件。
- 词条通过语言与重复校验。

缺少可选配图不影响 `ready`。缺少必需文字或任一音频时不得进入新词队列。

## 4. 运行时词库加载

不再把全部词条通过 TypeScript 静态 import 塞入单个 JS 文件。

### 4.1 文件组织

- 英语和韩语分别构建词条数据与索引。
- 词库按稳定顺序分片，每片包含固定数量的词条。
- 单独维护轻量索引，包含 ID、词头、规范化词头、中文摘要、等级、来源和所在分片。
- 单词、短语、例句音频放在独立静态媒体目录，不参与 JS 打包。

### 4.2 页面读取

- 学习首页只读取轻量统计与调度所需数据。
- 生词本按当前语言和筛选条件分页读取，不一次渲染全部词条。
- 搜索使用当前语言索引，切换语言仍保留筛选类型并清空搜索词。
- 学习 session 只保存单词 ID；进入学习页时按 ID 读取当前所需词条，避免载入整库。
- 词条详情按需读取完整释义、短语、例句和媒体地址。

现有自定义词继续从本地存储读取，并与内置词使用相同调度规则。

## 5. 音频生成、缓存与播放

### 5.1 构建期生成

- 英语使用一致的标准英语语音，韩语使用一致的标准韩语语音。
- 单词、短语和例句分别生成 MP3，不能用单词音频拼接短语或例句。
- 构建过程支持断点续跑，已通过校验且文本未变化的音频不重复生成。
- 文本变化后，对应内容哈希改变，旧音频不再匹配。
- 每段音频必须通过文件存在、非空、可解析和实际时长校验；静音、占位或失败响应不得进入媒体清单。

### 5.2 浏览器使用

- 日常播放读取本地静态媒体文件，浏览器按正常 HTTP 缓存策略缓存，不要求首次播放再配置 TTS 服务。
- 音频地址由词条 ID、内容类型和文本哈希确定，避免修改文本后误用旧音频。
- 学习记录与音频缓存分离；清除浏览器媒体缓存不得删除学习状态。
- 如果音频文件不可用，保留错误与重试状态，当前步骤不能继续。

### 5.3 播放门禁

继续沿用现有规则：

- 只有真实 `onEnded` 能解锁下一步。
- 重播、切后台、中断、加载失败和播放失败撤销当前音频完成状态。
- 不使用计时器推断播放结束，不提供拖动、快进或跳过。
- 三段音频使用递增请求 ID 防止旧播放 Promise 影响新播放。

## 6. 配图策略

- `imageUrl` 改为可选内容，不再作为所有内置词条进入学习队列的必要条件。
- 有可靠配图时正常显示。
- 无配图或图片失败时显示包含单词和语言标识的文字卡片，不使用虚构图片 URL 或“生成中”占位图。
- 现有 8 个词条的真实配图继续保留。
- 配图补充与文字、音频构建解耦，不阻塞完整词库学习。

## 7. 生词本与学习体验调整

### 7.1 大词库浏览

- 默认展示当前语言词条的分页结果。
- 支持按全部、学习中、已掌握、我添加的筛选。
- 增加按等级浏览的信息展示，但不改变已确认的四类筛选结构。
- 词条显示来源与等级；学习中词条继续显示 D 阶段和到期日。
- 搜索无结果、筛选无结果和真正空词库保持不同提示。

### 7.2 学习顺序

- 新词按稳定、可复现的顺序分配，避免每次启动随机变化。
- IELTS 可按考试频率与学术标签安排优先级。
- TOPIK 默认按 1 级到 6 级递进，高级重点标签用于展示和筛选，不直接跳过基础等级。
- 复习始终优先于新词，逾期复习按原到期日排列。
- 每种语言每日新词上限仍为独立设置的 1–200，默认 30。

## 8. 本地数据与迁移

- 不删除或重置 `studyStates`、`daily`、`settings`、`session`、`wordbookView` 和自定义词。
- 保留现有 8 个内置词的 ID，确保既有学习状态继续匹配。
- 若恢复中的 session 引用的词条已不存在，跳过失效 ID 并保留其他进度；不得清空全部学习数据。
- 学习记录继续使用现有版本化存储键；词库文件升级不需要迁移学习记录。
- 清除媒体缓存只影响浏览器重新读取媒体，不删除本地学习记录。

## 9. 异常处理

- 原始来源不可用：构建停止并报告具体来源，不生成虚假词条。
- 文本缺字段：列出词条 ID 和缺失字段，不标记为 `ready`。
- TTS 部分失败：保留已成功音频，断点续跑仅处理失败项。
- 音频与文本哈希不一致：拒绝发布该媒体清单。
- 词库分片读取失败：显示可重试错误，不影响其他本地数据。
- 媒体播放失败：阻塞当前步骤并允许重试，图片失败不阻塞学习。
- 本地存储空间不足：明确提示并保留已提交学习记录，不静默清空数据。

## 10. 验证与验收

### 10.1 构建校验

- 输出英语、韩语各自的去重词数和等级分布。
- 检查所有 ID 稳定、唯一且不依赖数组位置。
- 检查英语释义顺序所需字段和韩语英文、韩文、中文字段。
- 检查同语言无重复规范词头，学习 session 不混入另一语言。
- 检查所有 `ready` 词条的三段音频存在、可解析且时长合理。
- 检查无占位图片、空音频、模板例句或未标记来源的内容。

### 10.2 领域回归

现有调度、连续学习天数、语言隔离和音频步骤测试必须继续通过，并新增：

- 大词库分片后每日新词数量仍不超过设置目标。
- 重复构建不改变词条 ID 和学习记录关联。
- 配图缺失不影响入队，音频缺失必须阻止入队。
- 搜索、筛选和分页只作用于当前语言。
- 现有 8 个词条的学习状态在词库升级后仍可恢复。

### 10.3 浏览器验收

- 首屏与生词本不会因整库加载而长时间阻塞。
- 大词库搜索、翻页、详情打开和学习队列可用。
- 三种音频均按真实播放结束解锁，缓存命中与未命中行为一致。
- 刷新页面后学习记录保留；清除媒体缓存不删除学习记录。

## 11. 完成标准

只有同时满足以下条件才视为完整词库可用：

1. 选定的 IELTS 与 TOPIK 分级词目全部经过构建并有可追溯结果。
2. 所有进入学习队列的词条具有完整必需文本与三段真实音频。
3. 词库构建报告没有未解释的缺失、重复或媒体校验失败。
4. 大词库下首页、生词本、搜索、详情和学习流程均可使用。
5. 现有学习记录与自定义词不受影响。
6. 日常学习不需要配置微信、云函数或运行时 AI 服务。
